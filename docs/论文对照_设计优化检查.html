3 · 本回合已落地：洞察综合层（InsightBench 驱动）

新增 scripts/insight.py + 接线

论文：Sahu et al. 2024 InsightBench (arXiv:2407.06423)

做什么：synthesize(dsl, result_df, audit, reg) 按查询类型确定性合成三件套：

  • summary：一句话洞察（C→候选等级分布+头部；B→TOP1 维度占比+长尾；A→命中行+主集中大区）。
  • action：可执行动作（来自体检 flags，如"派单前先补采…"或"可优先在 X 投放"）。
  • followups：2~3 个建议的下一步分析问法，形成分析飞轮钩子。

为什么稳：① 零 LLM 依赖——规则只吃"结果形状+体检"，保住本 Skill 无 LLM 也能跑的特性；② 空结果自动降级；③ 接线覆盖 CLI 单查、--json(新增 insight 字段)、会话 ask/:fix 三处。

验证：新增测试 T35，全量回归 35/35 通过；真实 C 类查询实拍正确输出"共 50 个候选…头部候选…可执行动作…建议下一步"。

4 · 一个诚实的再发现

重读源码确认：route_metric 已经是 coverage 驱动的（取候选字段里该业态覆盖率最高者），即"按业态路由"本质上是手写候选集 + 数据驱动的 CFD 式选择。因此本回合没有重复造轮子去"重写路由"，而是把优化预算投向论文指出的最大缺口——端到端洞察（InsightBench）与后续策略规划（Zhu 2025）。这也呼应 Zhu 论文的反直觉结论：继续加码"理解层"边际收益递减，真正该投的是"规划与主动向前走一步"。
